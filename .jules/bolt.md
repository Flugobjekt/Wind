## 2024-05-19 - O(1) Task Cancellation Optimization
**Learning:** Legacy scheduler shims (`WindDispatchedTasks`) in Folia implementations often cache tasks globally, resulting in `cancelById` needing to iterate over all plugins' task maps to find the specific task to cancel, which has an O(P) complexity (where P = number of plugins). By directly associating the `Plugin` object with each task inside the `Entry` tracking object, we can remove this iteration and convert task cancellation by ID from O(P) to O(1), ensuring faster and safer garbage collection/cancellation for recurring or short-lived plugin tasks.
**Action:** Always check if a globally unique ID (like a task ID) that is mapped hierarchically (e.g., `Plugin -> Map<ID, Boolean>`) can be backward-referenced to avoid full map traversal when reverse lookups are frequently needed.
